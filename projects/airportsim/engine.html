What carries the name

In AirportSim's source tree, src/engine/ contains exactly two files: halcyon.h — the identity header, defining HALCYON_NAME "Halcyon 2.5D" and HALCYON_VERSION "2.5.0" — and boot.c, which runs the boot sequence: the Section Zero studio card, the "powered by" card and title, the F3 developer overlay, and the F2 credits. That is the whole of the "engine" as a directory: a branding and boot layer. The F3 overlay it opens, though, grew well past a boot layer's ambitions: WP-09 developed it into the game's full Development Mode — a complete diagnostic environment of eight increments, finished on 2026-11-03 — built on the retained engine below.

What actually renders

The renderer the name sits on lives in the flat src/ tree: an SDL_RenderGeometry triangle batcher (render.c, render_layout.c) with an isometric projection (iso.c) and painter's-sort drawing. It is this game's own work, written for this game's 2.5D presentation. The studio Engine Registry records the relationship precisely: the audit found no evidence establishing a shared engine codebase between this layer and the studio's other games — see the Engine Laboratory for the full, qualified finding.

The version number

No recorded lineage

"2.5.0" was assigned at birth

halcyon.h was introduced in commit 626ec77 (2026-10-29) as a boot/branding module added to an already-working renderer, and it has exactly one commit in its history: the version was "2.5.0" in that first commit and has never changed. No 1.0 or 2.0 exists anywhere in the project's history or changelog, and why that number was chosen is not recorded. It is not a point on Blacksite's Halcyon scale (whose 1.0 → 2.0 → 3.0 lineage is documented), and the two numbers should never be compared.

Recorded open item

Documentation discipline · Not yet in force

Engine changes have no changelog of their own

Because nothing records engine-layer changes separately, the version constant could drift from the code unrecorded. The Engine Registry's recommended control — an explicit engine line in the game's changelog practice — is adopted at the game's next documentation pass. Until then it is recorded here as an open item, not a practice.

The verdict — and what is not claimed

The engine review this page once anticipated has happened: on 2026-11-01 a full engine assessment and mathematics audit examined the engine and the simulation's mathematics end to end, and its verdict was RETAIN the engine — no replacement was undertaken, and none is planned. Development Mode — the phase the old order placed after that review — is likewise complete (WP-09, eight increments, 2026-11-03). Engine claims here are graded by evidence class, as everywhere in the studio: Linux tests; the MinGW cross-compile (producibility only); Wine (preliminary, never called Windows verification); and native Windows runtime — a release gate, today exercised by the native battery on the owner's rig at every merge (the four classes are set out in the Engine Laboratory). Nothing beyond that record is claimed: this page describes the engine exactly as it stands in the current development build, 0.6.0-alpha.2.
