Lesson — FND-015, fixed 2026-11-03 (PR #41)

Test processes must not share a save folder

The suite's test processes were sharing one save folder, so tests could see — and be confused by — each other's saved games. It is the kind of fault that manufactures intermittent failures and hides real ones. The fix isolates each process's saves; it is recorded here because the lesson generalizes: a test's environment is part of the test.

How to read the grades

Implemented — the functionality exists in the code. This does not establish that it behaves correctly.
Demonstrated — a relevant test or reproducible scenario shows it works under the tested conditions. Not automatically reliability everywhere.
Established — evidence supports the behaviour across a meaningful range of conditions or long-running tests, within the stated scope.

Two different kinds of testing support these grades, and they are not interchangeable: unit/simulation tests exercise rules headlessly (fast, exhaustive, blind to whether a player can actually do the thing), while end-to-end flows drive the real game through scripted player-level scenarios. A feature needs the second kind before it can be called demonstrated as gameplay.

K8 · Open — replacement in design (2026-11-07)

The save format itself is fragile — a clean-sheet replacement is in design

The survey behind this entry (2026-11-07) measured the format as it is: a save file is the game's live state written to disk as one raw memory dump, and compatibility across its thirteen versions rests on frozen size numbers and byte-shifting patches — there are no per-version migrations at all. Three of the last four version bumps exist only because state hiding outside the saved block was found lost, or a field changed width mid-structure. Worst, a save from the 0.4 era passes the file's own integrity check and then crashes the loader — and because the load screen previews every save to draw its list, a player with such a file crashes by merely opening that screen. The owner's ruling: no patch on the old design. A replacement is in design — named, individually versioned sections written field by field; a loader that cannot crash, on load or on preview; damage contained to the damaged section, with a warning, while the rest loads; and one one-way importer for every old version, after which the old format retires. The current format keeps working, guarded by the existing tests, until the replacement lands. Closes when: the new system ships with the full fixture corpus — every old version, plus the hostile-file set — importing or refusing cleanly, and the crash class is closed by construction, not by another guard.
