The held release — the evidence for “held”

Version 1.5.0 was built and packaged on 2026-10-28 (game archive, 2,546,319 bytes, checksum recorded in the project's releases registry) and the project owner placed it on hold the same day. The build tag v1.5.0 exists in the repository as a historical marker of that build; the registry states explicitly that it is not a published release. The package itself remains in local studio storage only.

The closing state (2026-11-02)

Development was cancelled by the owner's decision of 2026-11-02 — a concentration decision: the studio's effort goes to AirportSim, and WorldForge was shelved at the same time (2026-10-31). The project's final state, preserved as it stands: the private repository and the working tree at commit 98e8bca; version 1.5.0 built, packaged, and held — never published, no GitHub Release, no download. The tree and its records are retained as a design reference. Nothing in this section is a work in progress, and nothing here will quietly change: a status change would take an owner's decision and new evidence, in that order.

Known items — shown, not hidden

History · Partial by construction

The repository's history begins at the 1.3.0 transfer

The pushed history's root commit is the snapshot transferred into this development line in October. The original Grok-era development (up to 1.2.2) is preserved as that snapshot and in studio-side records — not as a full commit history, because that history was never in this tree. Nothing was fabricated to fill the gap; if a fuller original history is ever recovered, it will be added as evidence, not woven in silently.

Unverified in this environment

Windows build gates not re-run

The Windows cross-build and its Wine test gates were verified when 1.5.0 was built (per the project changelog) but could not be re-run during the transfer — the cross-compilation kit and Wine are not present in the current environment. Recorded as not re-verified, not as failed.

Documentation · Stale

The in-tree agent instructions describe a retired workflow

The project's internal instructions still reference a virtual-machine workflow that the studio retired. A documentation refresh is recommended as a future, separate step; the transfer deliberately changed no project documents beyond adding the releases registry and CI.

Platform limitation

Branch protection is unavailable on the account plan

As with the studio's other repositories, enforced branch protection returns an authorization error on the current GitHub plan; the control is convention — changes land through reviewed pull requests. Recorded so nobody assumes a technical enforcement that does not exist.
